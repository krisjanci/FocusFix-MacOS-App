# Projects and tasks verification — 2026-11-23

## Implemented behavior

- Task uses a document icon and replaces the full main canvas in place. Profile controls, app logo/title, recording-status statement, streak, appearance control, and large work buttons are hidden from the task canvas and its accessibility tree. The original main content remains the size reference, so navigation does not resize the window. Groups/Analytics and their footer controls remain independent. Actionable permission/error messages remain available within tasks.
- A single bordered arrow-left button keeps the Badges-style 28 × 22 label frame beside Projects or the selected project name. Page titles now use 23-point rounded semibold type, slightly smaller than the main FocusFix title’s 25 points. It returns from a project to Projects and from Projects to the timer. Project editing cancels one level back. Escape cancels a name draft, then exits Edit mode, before page navigation. No separate no-project action appears in the task interface; ordinary timer Start work infers no project.
- Projects have stable IDs, editable colors, and ordered task checklists. Exactly one built-in Random Tasks project has a protected name and cannot be deleted. Legacy catalogs gain it atomically; an existing matching folder is adopted without changing its ID/tasks. Other project names remain editable, and deletion asks before removing entries. Task-row play actions explicitly start or switch work; browsing/editing never start recording. Each project offers Untasked Work.
- Explicit successful work actions promote their project to the front and persist lastWorkedAt. Opening, editing, completion, or automatic assignment reconciliation does not promote projects. Drag/drop and Move up/Move down allow manual project order, including Random Tasks. Manual order survives reload until a subsequent work action promotes a project again.
- A tick appears immediately on completion. At three seconds the row fades, shrinks to 85%, swipes sideways, and settles after older completed tasks. Canonical order stays independent of completion; reopening restores that position. Completed tasks also support manual footer ordering through an optional completedTaskOrder catalog field; new completions still append last. Legacy catalogs fall back to completion timestamps. Dragging supports placement before/after rows, including the last row. Accessible actions support Move up/Move down; row overflow menus have been removed. Reduce Motion fades and reorders without shrinking or swiping. Pending moves cancel on uncheck/deletion/navigation and completion dates survive relaunch.
- Starting from a task owns the exact new Work boundary. Switching a task/project checkpoints recording without resetting the work target or timer. Completing/deleting the active task changes subsequent work to Untasked Work; deleting its project changes to no project. Catalog renames/colors affect future snapshots and the current tint without rewriting earlier history. Reopening a task does not resume it automatically. New work periods start without a project; breaks retain the assignment.
- Assignment history intersects snapshots with observed normal-phase Work coverage. Breaks, check-ins, awaiting return, Unknown context, unavailable gaps and uncheckpointed tails are excluded. Segment rotation uses the same logical elapsed basis and carries the current choice forward.
- Task and Untasked Work play controls are white icons in 34 × 26 teal rounded rectangles. Successful play immediately returns to the main timer; recording/permission/save failures retain the task interface for attention.
- One Edit/Done control replaces per-row three-dot menus. Red X controls replace task play controls and appear beside removable projects. Clicking names in Edit mode opens a focused inline field with selected text; Enter, the checkmark, or Done saves. Invalid names retain the draft/error. Random Tasks remains protected; color controls remain editable. Finished rows regain normal size/opacity while editing so their controls stay usable.
- Live drag delegates update a teal insertion line with a leading dot at the measured row midpoint, above or below the target before release. Project/task and cross-project moves are rejected when incompatible; tasks remain within their current unfinished/completed section. Drop exit/release clears the guide. Local typed UUID tokens must match the exact UTF-8 provider payload before a move can be applied.
- While working on an assigned task, the main timer has a green outlined Finished task capsule matching Work target padding/font. It marks the catalog task complete, switches subsequent work to Untasked Work in the same project, and preserves timer/target credit. The chip is absent during breaks, idle/no-task work, and after successful completion. Catalog save failure keeps the task active and shows an error.
- Local catalog and assignment files save atomically. Read/save failures keep existing bytes/published state and expose errors. Legacy sessions remain readable without assignment sidecars. Old tags remain in history/exports; new work has no tag-selection route.
- The private sidecar is included in local folder exports. Development/research upload allowlists exclude it, and names are absent from shared recording metadata and social progress. History reads detailed coverage off the main thread on request.
