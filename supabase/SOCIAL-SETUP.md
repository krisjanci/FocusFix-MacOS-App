# Private groups and streak protection

Apply `migrations/202610280001_private_groups.sql` after the existing account and consent migrations in the same Supabase project. This is an additive schema change; no research setting or billing configuration changes. The new RPC must be deployed before the updated app can sync groups. Existing app versions continue using their current endpoints. The app never runs migrations automatically. The migration was applied to the configured FocusFix project (`ltgyhstpbiocuxvyjpcb`) through its signed-in dashboard on October 27, 2026. The deployed function body matches the checked-in source; all six tables remain private and research collection remains disabled. See `verification/social-deployment.json` and `verification/social-deployment.jpg` for results.

The app uses its existing public account configuration and authenticated access token to call `rest/v1/rpc/social_state` with `p_action` and `p_payload`. Supported actions are `sync`, `create`, `join`, `leave`, `delete`, `reset`, and `remove`. Payloads include the account's initial timezone and activation instant, at most 200 immutable duration summaries (`id`, `kind`, Unix `at`, `seconds`), and relevant action fields (`name`, `code`, `group`, `member`). Responses contain the canonical timezone, personal progress/freeze ledger, and only groups of which the caller is currently a member. Creator-only invite codes and photo-free member presentation are included in those groups. Invalid invites return an `error` while retaining the rate-limit attempt; other validation failures roll back the request.

All six social tables enable RLS and deny direct anonymous/authenticated table access. Only the security-definer RPC has table access, with a fixed empty search path and explicit caller/membership/creator checks. Invite codes are random 128-bit values, resettable by creators. Join attempts are limited to ten per account per hour. Groups support up to 50 members; accounts can join up to 20 groups. Account deletion cascades through social summaries, owned groups and memberships. Removing or leaving a membership deletes its score history; joining again starts fresh.

Group progress starts only after explicit opt-in in Groups. Work durations are coalesced into short summaries, without raw input events, survey scores, break labels, email addresses or photos. Outboxes are stored separately by service origin and account UUID. Submitted event IDs are never edited, including after a lost response. The server deduplicates retries. A persisted scoring timezone controls midnight and DST allocation on every device. Work that spans joining is clipped to the membership start; qualifying breaks must begin after joining. Weekend work and breaks can earn points, but weekends do not require work for the weekday streak.

Three freeze tokens are available per calendar month, with no rollover. An account-row lock serializes sync and freeze decisions across devices. Missed days are processed in date order from activation. Freezes preserve an established weekday streak without adding streak days or leaderboard points, and cannot cover adjacent calendar dates. Friday and Monday are allowed. Late offline work deterministically replaces unnecessary freezes, returning their tokens and reconciling later decisions. Offline results are marked pending until sync.
